# ЛР7 Эмбеддинги и семантический поиск

Локальный поиск по 40 синтетическим фрагментам регламентов ИБ. 16 запросов с эталоном зафиксированы до измерений; 288 поисков, три повтора, k=1/3/5. Модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, ревизия `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`, CPU, 384 координаты, L2-нормализация.

## Запуск в PyCharm 2025

Откройте папку репозитория. Создайте Python 3.12 venv и выберите его интерпретатором проекта. Команды ниже выполняются из `lab07-semantic-search`:

```sh
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python src/build_index.py
python src/evaluate.py
python src/search.py "что делать если украли пароль" --k 3
python src/test_core.py
```

LM Studio и API-ключ не нужны. При первом запуске скачиваются веса модели. Для повторной работы без сети задайте `HF_HUB_OFFLINE=1`; при отдельной локальной копии модели — `LAB7_MODEL_PATH`. В PyCharm это Environment variables в Run Configuration. Программный эксперимент выполнен с офлайн-переменными после отдельного скачивания весов. `evaluate.py` повторно строит индексы и перезаписывает результаты; перед повтором сохраните нужные старые файлы.

## Алгоритм и данные

TF-IDF (словесные 1–2-граммы, без лемматизации) сравнивается с нормализованными эмбеддингами и полным NumPy-поиском. Ограничение 512 токенов одинаково во всех схемах, проверяется без скрытого усечения; максимум в опыте 239. Это увеличение стандартного лимита модели 128, не дообучение. FAISS/ANN не используется.

`data/corpus.jsonl`: id, text, source, category, section, access_group, start/end. `queries.jsonl`: вопрос и релевантные ID. Разметка создана ассистентом до поиска и не является независимой человеческой оценкой. Пять исходных документов — `data/documents/`. `small`: окна 400/80 символов; `large`: 1000/200. Релевантное новое окно содержит не менее половины исходного эталонного абзаца.

## Результаты при k=3

| Схема | Метод | Precision | Recall | MRR | мс |
| --- | --- | --- | --- | --- | --- |
| base | tfidf | 0.167 | 0.438 | 0.502 | 1.39 |
| base | semantic | 0.271 | 0.781 | 0.683 | 39.23 |
| small | tfidf | 0.167 | 0.396 | 0.493 | 1.06 |
| small | semantic | 0.312 | 0.771 | 0.819 | 42.97 |
| large | tfidf | 0.250 | 0.604 | 0.602 | 1.63 |
| large | semantic | 0.354 | 0.885 | 0.797 | 60.67 |

Семантика помогает при перефразировании: для вопроса о похищенном пароле правильный `access_01` стоит первым вместо 11-го места TF-IDF. Но запрос о синхронизации времени TF-IDF решает лучше: 1-е место против 5-го. Семантическое кодирование существенно медленнее. MRR вычислен по полному ранжированию, не MRR@k. Схемы имеют разное количество кандидатов и эталонных окон, поэтому их показатели нельзя сравнивать без этой оговорки.

## Файлы и защита

- [Word-отчёт](report/lab07_report.docx) и [текст отчёта](report/report.md).
- `results/runs.json` — полные ранжирования; `search_results.csv`, `summary.csv`, `metrics.json` — измерения и сводки.
