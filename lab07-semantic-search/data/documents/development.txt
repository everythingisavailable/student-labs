Зависимости приложения фиксируют по версиям и проверяют на известные уязвимости. Обновления сначала прогоняют через тесты. Наличие библиотеки в общедоступном каталоге не означает, что она безопасна или подходит по лицензии.

Входные данные для SQL передают как параметры запроса. Склеивание SQL-строки с пользовательским вводом может изменить смысл команды. Экранирование вручную не заменяет параметризованные запросы и минимальные права учётной записи базы.

Пароли пользователей хранят как результат специализированной функции выработки ключа с индивидуальной солью. Обычный быстрый SHA-256 без дополнительных мер не подходит для хранения паролей. Параметры стоимости подбирают под допустимую нагрузку.

Приложение проверяет полномочия на сервере при каждом обращении к объекту. Скрытая кнопка в интерфейсе не запрещает прямой запрос. Пользователь одного подразделения не должен получать чужой документ по изменённому идентификатору.

В журналы приложения не записывают секретные токены, пароли и полные персональные данные. Для диагностики используют безопасные коды ошибок и идентификатор запроса. Перед отправкой отчёта поддержки проверяют состав полей.

Сборка выпускается из зафиксированного коммита с протоколом проверок. Контрольная сумма помогает проверить целостность файла, а цифровая подпись — его происхождение при доверенном ключе. Эти механизмы не доказывают отсутствие ошибок в программе.

Документы для семантического поиска сопровождаются метаданными источника и группы доступа. Ограничение прав применяется до выдачи результатов и передачи контекста модели. Векторы не считаются шифрованием и защищаются вместе с исходным текстом.

Текст найденного документа является данными, а не управляющей инструкцией для помощника. Команда игнорировать правила внутри документа не должна менять системное поведение. Ответ проверяют по реально найденным источникам и их идентификаторам.
