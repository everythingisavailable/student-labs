# Лабораторная работа 4 — Оценка качества LLM

Первичная классификация синтетических событий информационной безопасности. Сравниваются две конфигурации `google/gemma-3n-e4b`: исходные `prompt_v2.txt` (A) и `prompt_v4_json.txt` (B) из ЛР3 **без изменений**. [Происхождение и SHA256](prompts/provenance.json). A использует шесть текстовых полей; B — шесть полей JSON, примеры и уточнения из ЛР3.

Первоначальные хеши относятся к локальным байтам до Git. Для проверки после клонирования на другой ОС есть [хеши с нормализацией CRLF в LF](prompts/provenance-portable.json): текст промптов не изменяется, учитывается только преобразование переносов строк Git.

## Запуск в PyCharm 2025

Открой корень репозитория. Выбери Python 3.10 или новее. Дополнительные библиотеки не нужны: HTTP, CSV, JSON и метрики реализованы стандартной библиотекой; формулы проверяются тестами. Это техническая замена рекомендуемых в методичке SDK, pandas и scikit-learn.

Запусти LM Studio, загрузи `google/gemma-3n-e4b` и включи сервер на порту 1234. Для этапа judge должна быть доступна отдельная модель `gemma-4-12b-coder-fable5-composer2.5-v1`. Идентификаторы можно изменить в конфигурации ДО нового запуска. Файл `.env` нужен только для изменения адреса/ключа; пример — `.env.example`, настоящий `.env` не публикуется.

Из терминала PyCharm в корне репозитория:

```shell
python lab04/src/test_evaluate.py
python lab04/src/evaluate.py --with-judge
```

Одна команда выполняет 60 основных запросов, 30 дополнительных повторов и 20 запросов судье; сохраняет отдельную папку с UTC-датой, снимками кода/промптов/набора/настроек, JSONL, JSON, CSV и автоматическим Markdown-отчётом. При использовании другой модели убедись, что она помещается в память. Загрузка модели может увеличить время первого запроса.

Возобновление конкретного запуска (подставь фактический каталог):

```shell
python lab04/src/evaluate.py --run lab04/results/20261008_131156_utc
python lab04/src/evaluate.py --run lab04/results/20261008_131156_utc --judge-only
python lab04/src/evaluate.py --run lab04/results/20261008_131156_utc --summarize-only
```

Повторно уже сохраненные запросы не выполняются, в том числе неуспешные. Автоматических ретраев и удаления плохих ответов нет. Для чистого повторного эксперимента запусти без `--run`.

## Методика

По 10 обычных, сложных и граничных событий; 15 normal, 15 suspicious. Основная метрика — F1 положительного класса, дополнительно Recall из-за риска пропуска события. Эталонная категория отображается в бинарную метку; `unknown` становится `abstain`. Ошибка формата — `parse_error`. Все исходы остаются в знаменателе Accuracy, положительные отказы/ошибки — в знаменателе Recall. Матрица 2×4 показывает их отдельно.

Строгий формат проверяется по собственному контракту A/B; JSON-доля A ожидаемо низкая и не является ошибкой его текстового контракта. Markdown-ограждение JSON у B — нарушение, автоматического исправления нет. Дословность evidence проверяется отдельно, не смешивается с синтаксической валидностью. Условия генерации одинаковы, но длина системных промптов различается.

Фиксированные 10 пар проверяются по четырём критериям 0–2. Оценки ассистента отмечены `assistant_review` и не выданы за ручные оценки студента. Файл `human_review_template.csv` предназначен для обязательной самостоятельной контрольной проверки. Сравнение с judge до ее заполнения означает сравнение двух автоматизированных оценок, а не human vs LLM.

После заполнения всех 20 строк (баллы 0–2; `hallucination` — `true` или `false`) выполни:

```shell
python lab04/src/compare_human.py lab04/results/20261008_131156_utc
```

Программа откажется считать незаполненную таблицу человеческой оценкой и после заполнения сохранит отдельные `human_judge_comparison.csv` и `human_judge_summary.json`. Их выводы нужно добавить в раздел сравнения отчёта перед сдачей.

Облачные сервисы для инференса не используются. Публикуются только синтетические события. Стоимость локального вычисления не оценивалась; «бесплатно» из этого не следует.
