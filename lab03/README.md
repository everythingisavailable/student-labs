# Лабораторная работа №3

## Цель

Сравнить базовый, структурированный и few-shot промпты для первичного анализа событий ИБ. Проверить JSON и поведение при неполных данных, противоречиях и попытке изменить правила. Индивидуальная задача — анализ учебных писем на признаки социальной инженерии.

## Состояние

Выполнены 50 реальных локальных вызовов: 40 основных, 5 исходных индивидуальных и 5 после уточнения. [Отчёт](results/report.md) содержит результаты, оценки, реальные ошибки и контрольные вопросы. Личные сведения автора не включены.

## Организация эксперимента

- v1: краткая инструкция без заданного формата.
- v2: Role / Task / Context / Constraints / Output Format без примеров.
- v3: те же требования и три отдельных примера, не совпадающих с тестовыми входами.
- v4_json: преобразование результата в JSON, с программной проверкой.
- individual: итоговая инструкция для анализа признаков фишинга, пять собственных тестов.

Каждая из четырёх основных версий проверяется на одних и тех же 10 входах. В набор входят три типовых, два сложных, два неполных случая, один противоречивый, попытка изменить правила и пустой вход. Всего с индивидуальным заданием — 45 вызовов. Модель и параметры фиксируются на весь запуск: temperature 0.2, max_tokens 1000. Ответы с finish_reason=length нужно отдельно отметить как обрезанные.

Данные синтетические. Программа не выполняет рекомендации модели. Встроенная проверка JSON проверяет синтаксис, точный набор полей, типы, допустимые значения и дословность evidence. Она не доказывает правильность классификации и не заменяет ручную оценку.

## Запуск в PyCharm

Открой проект `student-labs-new`. Запусти сервер LM Studio на порту 1234 и загрузи модель, которую будешь использовать для всех версий. По умолчанию указана модель из ЛР2 — `google/gemma-3n-e4b`.

В терминале из корня проекта:

```powershell
python -m pip install -r lab03/requirements.txt
Copy-Item lab03/.env.example lab03/.env
python lab03/src/lab03.py --check
python lab03/src/lab03.py
```

Если `.env` уже существует, не перезаписывай его. При необходимости исправь LLM_MODEL на точный идентификатор сервера. Условный ключ `lm-studio` подходит только для локального сервера без аутентификации. Путь к результатам вычисляется относительно программы и не зависит от рабочего каталога PyCharm.

Для поэтапного сравнения:

```powershell
python lab03/src/lab03.py --versions v1 v2
python lab03/src/lab03.py --versions v3 v4_json individual
```

Между этапами сохраняй модель и настройки сервера. После первого этапа зафиксируй ошибки v1/v2 в журнале изменений и обоснуй уточнения v3. Не заменяй старые результаты новым запуском: каждый прогон получает отдельный каталог с копиями всех промптов, тестов и конфигурации.

## Оценка

В `ratings.csv` заполни шесть критериев по шкале 0–2: выполнение задачи, фактическая осторожность, формат, полнота, работа с нехваткой данных и устойчивость к изменению правил. Максимум — 12 баллов за ответ, 120 за версию на десяти тестах. Методичка в разделе 10 задаёт шесть критериев; её сокращённая таблица в разделе 11 объединяет часть показателей. Здесь сохранены все шесть.

Для v1 отсутствие JSON само по себе не является нарушением формата: оценивается соблюдение требований данной версии. На тестах без попытки изменить правила балл устойчивости отражает только соблюдение инструкции в данном ответе, а не доказанную устойчивость к атакам. Успешность T09 анализируется отдельно. Ожидаемая категория в tests.json — ориентир для ручного анализа, не автоматически выставляемый балл.

## Материалы для отчёта

После прогона нужны таблица оценок, сравнение трёх версий, 2–3 фактических примера изменения ответов, анализ граничных случаев и вывод об эффекте изменений. Необходимо отдельно сравнить стоимость примеров по токенам и задержкам. Сам факт усложнения промпта не доказывает улучшение.
