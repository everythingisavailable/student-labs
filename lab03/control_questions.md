# Ответы на контрольные вопросы

1. **Что такое промпт в прикладной LLM-системе?** Набор инструкций, контекста, примеров и текущих данных, определяющий задачу модели и ожидаемую форму ответа. В приложении это версионируемая часть конфигурации.

2. **Чем system prompt отличается от user prompt?** System задаёт постоянные правила приложения, user содержит конкретный запрос и переменный вход. Разделение ролей помогает управлять поведением, но не гарантирует защиту от изменения правил текстом входа.

3. **Для чего нужны Role, Task, Context, Constraints, Output Format?** Роль задаёт область ответственности; задача — требуемое действие; контекст — исходные сведения; ограничения — границы допустимого и поведение при неопределённости; формат — структуру результата для человека или программы.

4. **Чем zero-shot отличается от few-shot?** Zero-shot задаёт инструкцию без демонстрационных примеров. Few-shot добавляет несколько пар «вход — ожидаемый выход», чтобы показать границы классов и форму ответа.

5. **Когда few-shot может ухудшить результат?** При ошибочных или нерепрезентативных примерах, перекосе в сторону одного класса, противоречии примеров правилам, смешении примеров с текущими данными и нехватке контекста. Дополнительные примеры также увеличивают объём входа.

6. **Почему «верни JSON» не гарантирует корректный JSON?** Модель генерирует текст и может добавить Markdown, пропустить кавычки, вернуть неправильные поля или оборвать ответ по лимиту. Поэтому нужны json.loads, проверка схемы и обработка ошибок; корректный синтаксис ещё не означает правильного содержания.

7. **Почему промпт не является средством разграничения доступа?** Текстовая инструкция не блокирует операции на уровне сервера. Права проверяются доверенным кодом, а не решением модели. В этой лабораторной модель вообще не получает инструментов для изменения данных.

8. **Что такое критерий отказа?** Явное условие, при котором нельзя выдать содержательный уверенный вывод. Например, при отсутствии источника и контекста входа возвращается insufficient_data с перечислением недостающих сведений. Это позволяет безопасно передать случай на уточнение.

9. **Зачем версионировать промпты и фиксировать тесты?** Чтобы сравнивать изменения на одинаковых входах, связывать измерения с точным текстом инструкции, находить регрессии и повторять эксперимент. Одновременно нужно фиксировать модель и параметры генерации.

10. **Как понять, что проблема не в промпте?** Если исходных фактов нет, инструкции не восстановят их. Если корректные варианты промпта систематически дают одинаковые ошибки, возможны ограничения модели. Обрезание ответа связано с лимитом, ошибки соединения — с инфраструктурой, отсутствие нужных документов — с данными и поиском. Эти причины следует проверять отдельно от формулировки инструкции.
