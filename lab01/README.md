# Лабораторная работа №1

## Тема и цель

Программное взаимодействие с LLM через API. Цель — сравнить качество ответов и время выполнения одинаковых задач у трёх локальных моделей, чтобы выбрать модель с подходящим соотношением качества и задержки.

## Задачи

1. Подключить Python к локальному API.
2. Отправить каждой модели одинаковые 10 запросов по информационной безопасности, обработке текста и коду.
3. Измерить задержку и сохранить ответы и ошибки в CSV/JSON.
4. Оценить корректность, полноту, следование инструкции и практическую полезность по шкале 0–2.

## Технологии и структура

Python, `openai`, `python-dotenv`, стандартные `csv`, `json`, `time`; локальный OpenAI-совместимый API LM Studio. Код: [src/main.py](src/main.py). Отчёт и таблицы: [results/](results/).

Модели в отчёте: Qwen3.6-35B-A3B, Gemma-4-12B и Gemma-3n-E4B. Параметры программы: `temperature=0.2`, `max_tokens=2000`, тайм-аут 600 секунд.

## Как устроено решение и почему

Один клиент и один набор запросов используются для всех моделей: между прогонами меняется `LLM_MODEL`. Это сохраняет одинаковую процедуру сравнения. Настройки подключения вынесены в `.env`, чтобы не записывать ключ в код. `time.perf_counter()` измеряет длительность вызова. Исключение записывается в результат отдельного запроса, и серия продолжается. Проверка пустого `message.content` позволяет обнаружить формально успешный ответ без итогового текста.

CSV удобен для ручных оценок и таблиц, JSON сохраняет полные ответы. Поля оценок программа оставляет пустыми: баллы в отчёте выставлены вручную. После переноса в `src/` алгоритм эксперимента сохранён.

## Запуск

Нужны Python 3.10+ и работающий локальный сервер LM Studio по адресу `http://localhost:1234/v1`. Загрузите нужную модель и проверьте её точный идентификатор на сервере. Экспериментальные названия моделей взяты из отчёта; доступность конкретных сборок отдельно не проверялась.

Из корня репозитория в терминале PyCharm (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r lab01/requirements.txt
Copy-Item lab01/.env.example lab01/.env
```

В `lab01/.env` заполните `LLM_API_KEY`, `LLM_BASE_URL` и `LLM_MODEL`. Если локальная аутентификация LM Studio отключена, для требования SDK к непустому ключу можно использовать условное значение `lm-studio`; при включённой аутентификации нужен действующий локальный токен. `.env` не загружается в Git.

```powershell
cd lab01
..\.venv\Scripts\python.exe src/main.py
```

Рабочий каталог должен быть `lab01`, чтобы результаты сохранились в `lab01/results/`. Для запуска зелёной кнопкой PyCharm выберите интерпретатор `.venv` и в конфигурации запуска задайте тот же рабочий каталог.

Зависимости указаны диапазонами совместимости; точные версии исходной экспериментальной среды в отчёте не зафиксированы. Повторные ответы и задержки могут отличаться.

Для полного сравнения выполните программу по одному разу для каждой из трёх моделей, меняя модель на сервере и значение `LLM_MODEL`. Каждый запуск создаёт файлы с идентификатором модели и временем.

## Эксперименты и результаты

В отчёте представлены по 10 итоговых ответов каждой модели. Это результаты автора; при оформлении репозитория новые API-вызовы не выполнялись.

| Модель | Средний балл из 8 | Средняя задержка, с | Ошибки API |
| --- | ---: | ---: | ---: |
| Qwen3.6-35B-A3B | 7.9 | 42.600 | 0 |
| Gemma-4-12B | 6.7 | 10.260 | 0 |
| Gemma-3n-E4B | 7.6 | 6.556 | 0 |

Qwen выполнил строгие требования к JSON и таблице; обе Gemma добавляли Markdown-обёртку к JSON. Gemma-4-12B в двух заданиях переключалась на английский язык. В предварительном запуске Qwen лимита 600 токенов не хватало для получения итогового текста; после увеличения до 2000 все 10 ответов были заполнены.

Полные таблицы, оценки, ограничения и ответы на контрольные вопросы доступны в [отчёте](results/report.md). Исходные CSV/JSON с полными ответами сохранены в [results/](results/).

## Вывод

Qwen получил лучший средний балл, но работал заметно медленнее. Gemma-3n-E4B показала наиболее выгодное соотношение скорости и качества в данной локальной конфигурации. Скорость сама по себе не определяет качество: важно проверять содержание и соблюдение формата. Ручные оценки субъективны, задержки зависят от оборудования; повторяемость по нескольким прогонам в ЛР1 не исследовалась.
