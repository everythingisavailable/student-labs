# Отчёт по лабораторной работе 1

1. Цель работы

Цель работы — освоить базовый программный цикл взаимодействия с большими языковыми моделями через API и сравнить несколько моделей на одинаковом наборе заданий. В ходе работы требуется научиться отправлять запросы из Python, измерять задержку ответа, фиксировать ошибки, сохранять результаты и оценивать качество ответов по единым критериям.

В рамках эксперимента дополнительно проверялись корректность, полнота, следование инструкции и практическая полезность ответов. Для сопоставимости все модели получали один и тот же набор из 10 запросов и использовали одинаковые параметры генерации.

4. Реализация программы

Программа загружает параметры подключения из .env, создаёт клиент OpenAI, последовательно отправляет 10 запросов выбранной модели, измеряет время каждого вызова через time.perf_counter(), перехватывает исключения и сохраняет результат эксперимента в CSV и JSON. Для каждого вызова фиксируются модель, номер и текст запроса, время, ответ и сообщение об ошибке.

Фрагмент 1 — Создание клиента и вызов модели

client = OpenAI(api_key=API_KEY, base_url=BASE_URL, timeout=600.0)def ask_model(prompt):    started = time.perf_counter()    response = client.chat.completions.create(        model=MODEL_NAME,        messages=[            {'role': 'system', 'content': 'Отвечай точно и по существу. Сразу дай итоговый ответ.'},            {'role': 'user', 'content': prompt}        ],        temperature=0.2,        max_tokens=2000    )    elapsed = time.perf_counter() - started    answer = response.choices[0].message.content or ''    if not answer.strip():        raise ValueError('Модель не вернула финальный текст ответа')    return answer, elapsed

Фрагмент 2 — Цикл эксперимента и обработка ошибок

for prompt_id, prompt in enumerate(prompts, start=1):    try:        answer, latency = ask_model(prompt.strip())        results.append({            'model': MODEL_NAME,            'prompt_id': prompt_id,            'latency': round(latency, 3),            'answer': answer,            'error': ''        })    except Exception as exc:        results.append({            'model': MODEL_NAME,            'prompt_id': prompt_id,            'latency': '',            'answer': '',            'error': str(exc)        })

Полные ответы моделей не включались в отчёт, поскольку для анализа достаточно таблиц измерений и наиболее показательных наблюдений. Полные результаты сохранены отдельными CSV/JSON-файлами.

6. Обнаруженные ошибки и ограничения

В первом тестовом запуске Qwen при ограничении max_tokens = 600 часть запросов завершалась без ошибки API, но поле финального ответа оставалось пустым. Для устранения проблемы лимит генерации был увеличен до 2000 токенов, а в программу добавлена проверка пустого message.content. После исправления итоговый прогон Qwen завершился с 10 заполненными ответами из 10.

В окончательных прогонах всех трёх моделей ошибок API не зафиксировано. При этом обнаружены ограничения на уровне содержания: Gemma-4-12B в двух заданиях переключалась на английский язык; обе Gemma-модели добавляли Markdown-обёртку вокруг JSON при требовании вернуть только JSON; в отдельных ответах встречались неточности формулировок и опечатки.

Оценка качества является экспертной и частично зависит от интерпретации открытых заданий. Стабильность результатов при многократном повторении запросов в основной части не проверялась. Кроме того, измеренная задержка относится только к используемому компьютеру и конкретным локальным сборкам моделей; на другом оборудовании абсолютные значения времени могут существенно отличаться.

8. Ответы на контрольные вопросы

1. Что такое API и зачем он нужен при создании AI-приложений?

API — программный интерфейс, через который одна программа обращается к функциям другой системы по формализованному протоколу. В AI-приложении API позволяет программно отправлять запросы модели, получать ответы и встраивать LLM в собственные сервисы, ботов, аналитические системы и автоматизированные процессы.

2. Чем работа с LLM через API отличается от использования чат-интерфейса?

В чат-интерфейсе пользователь вручную вводит сообщения и читает ответы. Через API запросы формирует программа: можно автоматически обрабатывать большие наборы заданий, задавать параметры генерации, сохранять результаты, измерять время и интегрировать модель в информационную систему.

3. Какую роль выполняет system message?

System message задаёт общие правила, контекст и стиль поведения модели. Он имеет более высокий приоритет, чем обычный пользовательский запрос, и позволяет заранее определить требования к ответам, например точность, краткость или формат.

4. Почему нельзя сравнивать модели только по одному запросу?

Один запрос отражает только один тип задачи и может случайно оказаться особенно удачным или неудачным для конкретной модели. Для корректного сравнения нужен набор разных задач и единые критерии оценки.

5. Почему один и тот же запрос может давать разные ответы?

LLM генерирует текст вероятностно. На результат влияют параметры генерации, например temperature, а также особенности сэмплирования и внутреннего состояния. Поэтому даже одинаковый запрос может приводить к разным формулировкам.

6. Что такое latency и почему она важна для бизнес-приложения?

Latency — время от отправки запроса до получения ответа модели. Высокая задержка ухудшает пользовательский опыт, снижает пропускную способность системы и может быть критична для интерактивных или массовых бизнес-процессов.

7. Почему API-ключ нельзя хранить в публичном исходном коде?

API-ключ является секретом доступа. Если он попадёт в публичный репозиторий, посторонние смогут выполнять запросы от имени владельца, расходовать лимиты, создавать расходы или получать доступ к разрешённым ресурсам. Поэтому ключ следует хранить в переменных окружения или .env, исключённом из Git.

8. Какие данные нельзя отправлять во внешнюю LLM без соответствующих оснований и мер защиты?

Нельзя передавать реальные персональные данные, пароли, токены доступа, API-ключи, коммерческую тайну, закрытые документы организации и другие сведения ограниченного доступа. Для учебных экспериментов следует использовать синтетические или открытые данные.

9. Какие метрики классического машинного обучения подходят только для части LLM-задач?

Accuracy, precision, recall и F1 хорошо подходят для задач с однозначными классами или проверяемой разметкой, но плохо описывают качество свободного текста. Метрики вроде BLEU и ROUGE могут применяться к некоторым задачам генерации и суммаризации, однако также не заменяют содержательную оценку корректности и полезности ответа.

10. Почему высокая скорость модели не означает высокое качество?

Скорость характеризует только время вычисления ответа. Быстрая модель может пропустить часть задания, нарушить формат или дать фактическую ошибку. Поэтому latency необходимо рассматривать вместе с показателями качества.

11. Какие ошибки могут возникать при вызове API и как приложение должно на них реагировать?

Возможны ошибки авторизации, неверные параметры запроса, недоступность модели, превышение лимитов, сетевые тайм-ауты и серверные ошибки. Приложение должно перехватывать исключения, записывать ошибку в результат, не завершать весь эксперимент аварийно и, для временных сетевых ошибок, при необходимости выполнять ограниченное число повторных попыток.

12. Какие дополнительные критерии можно добавить при выборе модели для корпоративной системы?

Можно учитывать стоимость, требования к аппаратным ресурсам, конфиденциальность и место хранения данных, лицензию, длину контекста, устойчивость к ошибочным инструкциям, стабильность ответов, доступность сервиса, возможность локального развёртывания, аудит действий, поддержку нужных языков и совместимость с корпоративной инфраструктурой.
